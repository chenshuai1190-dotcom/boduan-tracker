# 复盘：代码接入与验收

日期：2026-11-06。范围：将静态原型接入 React 正式页面、全部功能入口与旧记录读取。用户已授权云端图片配置、自定义头像及 v10.7.9.567 发布；两份独立 SQL 已应用，生产预检、执行与真实上传证据见 `review-journal-cloud-configuration.md`。本文记录发布前验收，最终部署状态以对应提交的 CI、Vercel 与任务发布结论为准。

## 入口与界面

- `App.jsx` 懒加载 `ReviewJournalPage`，按用户 ID remount。
- 交易 → 全部功能 → 记录与复盘组 → 复盘；目标中的旧双栏目改为一个复盘入口，旧组件仍为兼容测试入口保留。
- 全部支持公开／私密范围：公开按公开时间倒序，私密按记录日期倒序，均忽略置顶；分类保留自己的完整记录及行内置顶图标。公开权限与点赞边界见 [公开动态说明](review-public-activity.md)。
- 点击博文正文或空白区域进入独立详情页；全文、图片、股票走势、市场快照和评论附件完整展示。列表取消右下角“查看记录”，保留评论入口。图片、股票卡片和更多操作仍使用各自交互。
- 顶部返回与浏览器前后退保留列表筛选、展开状态及滚动位置；详情采用当前页面内的私有 history state，不改变 URL，不提供公开分享链接。
- 复盘身份只读复用社区资料/头像 repository，不调用创建资料的 ensure 流程。昵称、本人头像路径及已解码图片保存在专用账号绑定的本机快照中；短期签名 URL/token 不落盘。进入时先同步显示快照，24 小时内不重复身份查询或头像下载；到期后台检查资料，头像路径未变则继续复用图片。本人修改资料成功立即失效，失败保留上一份成功显示；其他设备修改在下一次到期检查时同步。切号/退出清除当前快照并拒绝旧请求回写；损坏、超限、超过30天或不属于当前认证用户的缓存不可用，存储被禁用时降级为内存缓存。
- 新录入支持文字、日期、心情、表情、最多 4 个股票、市场收盘快照、最多 4 张图片。编辑保持原类型。
- 新增、编辑与恢复草稿时，从正文识别系统已知股票代码和具体公司名称，并按首次提及顺序自动关联；未知代码可用 `$` 明确指定。原手动关联不因自动识别被删除，新增自动关联只占剩余空位，满 4 只会提示。手动移除的排除意图仅保存在本地草稿，发布只保存最终股票数组，不增加数据库字段；历史博文不做批量改写。
- 手机/鼠标返回列表时聚焦无描边标题；仅键盘进入博文时恢复文章焦点，保留键盘提示，避免整条博文白框。
- 头像使用圆形裁切，裁去素材自身浅色外缘，无额外边框。

## 数据合同与上线前置

旧 `disciplines`、`review_logs` 继续保存正文，不迁移或删除原记录。`supabase/review-journal.sql` 已在用户授权后执行：

- 两表增加 `review_data` 和 `review_revision`，旧行默认空 metadata。
- 元数据保存股票、市场快照、图片路径、补记、心得记录日、日志置顶等。
- 编辑/删除带 user_id 和 revision CAS；旧版本更新同样递增 revision。
- 新建使用持久 operationId，唯一索引与内容校验保护网络结果不明后的重试。
- 私有 Storage bucket `review-journal-images`：仅本人目录可访问，JPEG/PNG/WebP，10 MB/张；展示用短期签名 URL。
- 图片只在发布时上传；无完整图片上传基础设施时明确报错。保存结果不明保留已上传引用，以便重试，不误删可能已提交的附件。
- 删除/移除附件只在对应数据库变更成功后尝试清理；存储清理失败可能留下本人私有孤立文件，正式运行需要配套清理治理。

其他环境迁移未执行时，老记录仍能读取，新富内容保存会明确提示未配置，不降级丢弃附件。当前云端已完成真实登录的上传、保存、刷新回读及签名图片预览；事务内对本人、其他身份和匿名角色做只读 RLS 断言，测试数据按用户授权清理。另有 PGlite 实际 SQL fixture 验证更新、CAS、重复迁移及写入隔离；该 fixture 不代表第二个真实账号已完成浏览器登录测试。

自定义头像入口：设置 → 社区资料 → 上传。选择原图后进行方形裁剪及缩放，压缩为 512×512；独立私有 `community-avatars` 桶上限 2 MiB，`community_profiles.avatar_path` 只保存本人文件路径，保留 `avatar_key` 兼容旧客户端。本人头像、复盘、收益分享与已授权社区参赛身份使用同一来源；失败回退预设。

## 走势与市场快照

`ReviewStockReplay` 只读取当前用户 stock_trades（非波段账本），列表卡片进入可视范围后自动查询现有鉴权股票对比 API。同账户、股票及日期范围共享在途请求，最多两路并发；离开页面取消不再需要的请求。该 API 需要两只股票，以 QQQ/SPY 作请求 companion，界面只展示选定股票。

一条记录关联多只股票时，通过 `ReviewStockCarousel` 按原关联顺序横向分页，每次完整显示一张卡片；支持原生滑动、股票代码切换及键盘左右键。单只股票不显示分页控件。列表、详情和评论附件复用同一呈现，股票卡片删除底部“只读回放”和“查看交易与走势”。整篇博文不再绘制焦点边框，昵称和股票标签均无下划线；键盘焦点使用局部轻背景提示。

博文正文使用 `ReviewStockText` 展示股票标签：沿用现有股票及公司名识别，每只股票第一次提及呈现为可点击的 `$代码`，后续重复提及保留普通文字且不重复 `$`。URL、邮箱和金额保留原样。该转换仅用于展示，不重写保存正文或打断编辑光标，历史记录也即时生效。点击标签进入当前用户该股票的博文列表，合并投资心得和复盘日志，精确匹配正文识别或已关联股票，不受此前分类/关键词影响；仍按时间排序。标签列表、独立博文及原列表之间的返回和前进保留各自阅读位置。

小图和回放默认展示全部交易区间，起点保留首笔交易前 183 天（最早 2000-01-01），右端延伸至最新完成收盘日，不再截取最近 65 个交易日。回放保留本次交易、1个月、3个月，增加6个月、1年和全部；局部区间仍以所选成交日期为中心。节点以成交日期对应的拆股复权收盘为锚，原始成交价单列，休市/缺失日不挪点、不补造时分秒。复盘记录日期与有效买入节点精确同日时标红，其他买入节点保持绿色；不依据创建时间或最近交易日猜测匹配。

### 历史持仓与实际交易的区别

- 软件启用时的手工记录可能汇总多笔历史买入：账本日期是录入日期，价格是平均成本，数量是汇总持仓。不得把这类记录解释为录入日的一笔真实成交，也不能拆造不存在的原始成交。
- 正式买入表单提供「实际交易 / 历史持仓」手动选择，新增与编辑均适用，TQQQ 与普通股票一致。仅明确选择才标记历史持仓；周末、休市、行情缺失、最早一条记录或平均价格都不能作为自动推断依据。旧记录默认保持实际交易，不批量改写生产数据。
- 类型由 `stockTradeRecordKind.js` 统一解析/序列化，使用现有 `stock_trades.note` 的独立版本标记，保留用户备注及未知内容。此标记只控制展示；不改 side、日期、价格、股数、手续费、持仓、成本或收益算法，不恢复缺失历史。备注展示不得泄露机器标记。
- 历史持仓在列表小图中提示「含历史持仓记录」，详情显示「录入日期 / 平均成本 / 持仓数量」；不生成 B/买入节点、不绑定当天或邻近日线，即使录入日恰好有行情也一样。实际交易缺少当天行情时，记录保留，并在已有行情覆盖范围内使用独立日期轨的空心节点；不使用平均成本或最近交易日收盘伪造价格锚点，范围外不挤到首尾。评论的「关联交易」只提供实际交易，避免丢弃类型后将历史汇总冻结成成交；已有评论引用仍保持保存时的快照。
- 回归必须覆盖工作日与休市日的历史汇总、普通缺行情交易、同日买卖、类型编辑回填/恢复、备注保留，以及全部动态/博文详情共用的小图与交易回放。展示类型变更也走 FULL，因为涉及正式账本持久化；部署结论应区分代码上线与既有记录是否已经由用户分类。

`SnapshotPicker` 复用现有 VIX/VIX3M、CNN Fear & Greed API。精确选已完成收盘日，缺项单独处理；选择其他来源日期需显式操作。保存值与实际来源日期冻结，阅读卡片不联网更新。

市场快照卡片保留标题处的实际来源日期和指标值，移除底部来源、“保存时快照”和记录日期差异提示。VIX / VIX3M 原始值严格大于 1 时，数值及状态使用系统红色；等于或低于 1 保持普通色。列表、独立详情、评论附件及录入预览共用同一呈现，已保存数据和分类规则不变。

正文由 `ReviewPostBody` 按实际排版高度判断是否折叠，不再按160字或6行截断。正文预算为手机小视口高度减去安全区和160px页面上下文，至少220px，并按完整行高向下取整；一屏内默认完整显示，超过才出现“展开全文/收起”。宽度、字体及视口变化重新测量，独立详情始终显示全文。

## 本地预览与验证

### 2026-11-07 评价评论

详情页的评论入口打开全屏「写评价」，保留普通文字评论，并可选填 1–10 分（五颗星、支持半星）、最多 8 个评价标签、最多 20 笔本人交易、市场与账户快照及最多 4 张图片。自定义标签按 Unicode NFKC、空白及大小写去重，每个最多 12 个字符；历史评论中的标签可再次选用。评分、标签与附件均可单独发布，不要求同时填写正文。

扩展字段保存在现有 `review_data.replies`，无需 SQL 迁移。旧评论继续读取。交易引用保存成交记录 ID、代码、日期、方向、原始成交价与股数；不写入或改动交易账本。账户快照仅读取本人、精确日期的正式 USD `pnl_snapshot_v2` 收盘记录及前后重建状态；拒绝未完成收盘、重建中、来源不明及跨用户数据。收益率从账本小数比例转换为百分数后冻结；杠杆仅在历史现金、负债和资产恒等式完整时显示，缺失不补零，也不使用今天的账户值推算。

评论追加先读取最新行，按 revision CAS 合并；同一 reply ID 与相同内容的重试幂等，冲突限次重读，不覆盖较新的正文、附件或其他评论。部分上传或发布失败保留草稿和已上传图片引用，允许移除草稿引用但不删除结果不明时可能已提交的云端图片。当前页面会话内按博文保留评价草稿，切换账号隔离；刷新或离开模块不承诺保留。

市场/账户引用默认从原记录日选择，实际来源日期始终显示，保存后冻结；缺项允许独立取消。股票走势仅使用已关联交易引用，拆股复权曲线与原始成交价继续区分。开发参数 `&reviewEvaluation=1` 提供隔离的评分、标签、交易及账户示例，所有示例保存仅在内存中生效。
