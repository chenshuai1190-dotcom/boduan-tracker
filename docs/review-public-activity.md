# 投资动态的公开、私密与点赞

公开动态基础迁移 `review_public_activity_20261108.sql`、作者评价公开迁移 `review_public_replies_20261108.sql` 与社区评价迁移 `review_community_evaluations_20261108.sql` 已应用。日期与评论回复需再应用 `supabase/review_public_chronology_replies_20261108.sql` 增量迁移，再发布前端；不能修改已经部署的旧迁移。迁移与发布结果以实际验收为准。

## 展示范围

| 入口 | 内容 | 排序 |
| --- | --- | --- |
| 全部 → 公开动态 | 所有已登录 Quote 用户明确公开的普通博文，包括自己的公开博文 | 原记录日期倒序；同日按原创建时间与 ID 排序 |
| 全部 → 私密 | 自己的私密博文及设置允许混入的自动时间线 | 原有记录日期倒序 |
| 复盘日志／投资心得 | 自己对应分类的全部博文，包含自己已公开和私密的博文 | 原有分类排序和置顶规则 |
| 时间线 | 自己的自动时间线 | 原有时间线规则 |

公开列表与详情沿用私密博文的作者行、正文及安全区布局；自己公开的博文通过右上角操作菜单直接编辑或删除，操作使用本人完整原记录，不能用公开投影覆盖原记录中的附件或评价。其他作者的博文不展示管理入口。

公开／私密切换只作用于“全部”。分类页始终是个人视角，不能把它们接到跨用户公开查询。自动时间线及其评价容器保持私密，不能通过修改 metadata 公开。

普通博文、评论和回复的作者行共用相对时间：不足 1 分钟“刚刚”、不足 1 小时按完整分钟、不足 24 小时按完整小时，满 24 小时后按完整天数；只按真实经过的时间计算，不按跨午夜次数。公开博文使用源记录创建时间 `publishedAt`，私密博文使用 `createdAt`，社区评价使用服务端 `createdAt`；精确时间的提示按查看者设备时区格式化，不混用作者提交的日历日期或服务器交易日。分钟级展示刷新只更新本地文本，不发起新请求。博文的原记录日期仍供复盘、市场快照和既有列表排序使用；时间线事件沿用事件日期，不能用回看/生成时刻冒充发布时间。

新作者评价首次实际提交时记录 `createdAt` 和设备当地日期，同一评价失败重试保持首次提交时刻，修改保持原时间。社区 API 继续剔除客户端 `createdAt` 并由服务端生成。旧评论仅有日期时保留该日期，不能补造午夜或根据父帖时间推算“几小时前”。私密转公开、编辑、刷新均不更新原创建时间。

首次新增博文默认“公开可见”；旧记录及旧草稿缺少 visibility 时仍按私密处理，编辑保留原可见范围。发布或编辑可以选择“公开 · Quote 用户可见”，保存后列表切换到对应范围。修改正文或切换可见范围都保留原记录日期与原创建时间；撤回后重新公开不改变日期或顶到今天，点赞仍按现有规则重新累计。补记旧记录时以用户选择的记录日期为准，不能用今天的入库时间代替。

当前设备通过按 userId 隔离的 localStorage，分别记住用户明确选择的“全部”浏览范围（feedScope）与新建博文发布范围（publishVisibility）。首次、缺失或非法值默认公开；两个偏好互不覆盖，只保存 public／private，不保存正文。旧记录和已恢复草稿优先使用自身范围，打开编辑或自动切换列表不更新习惯，只有用户显式选择时才更新。无登录用户不读写；存储不可用不阻断操作。发布界面保留范围选择，移除其说明提示；公开列表不再显示额外说明与独立刷新按钮，加载失败仍可重试。

## 数据与权限边界

- `disciplines`、`review_logs`、账本及完整个人资料继续使用原有本人权限。公开读取绝不能直接放开原表的 RLS。
- 迁移 `supabase/review_public_activity_20261108.sql` 创建 `review_public_posts` 安全投影。源记录写入触发器只提取正文、日期、股票代码、正文图片、市场快照及明确允许公开的评价字段；作者只返回昵称、头像预设及当前头像路径。
- 评价继承所属博文的可见范围，没有独立开关。用户已确认评价文字、评分、标签、图片、市场和账户快照、冻结交易引用一起公开；评价数据按既有正规模型逐字段投影，未知 metadata 和内部凭证不返回。主博文未明确授权的账户／交易原字段仍不外露。公开股票标签只筛选公开博文，不接入查看者或作者的私人买卖节点。
- 公开列表显示评论入口及总评价数量；详情对所有已登录用户展示公开评价，并允许发表评论或 1–10 分评分，评分可单独提交。作者仍使用本人的完整原记录新增、修改和删除自评；其他用户的评价写入独立社区评价表，绝不能借此修改作者原记录。评价显示实际评价者头像、昵称，每个人只能修改和删除自己的评价。评价编辑器按博文范围显示“公开可见”或“仅自己可见”。
- 源记录改为私密时，同一事务删除公开正文及作者自评投影和关联点赞；独立社区评价保留在原帖下，仅原帖作者可读取，其他用户不能继续读取或写入。再次公开时社区评价恢复可见；删除原帖时清理对应社区评价。新的公开正文、评价和图片读取都核验父帖当前可见范围。公开自评修改同步更新投影及更新时间，保留原公开发布时间与点赞。旧私密博文、自动时间线及其评价不通过回填公开。
- 公开仅指已登录的 Quote 用户；匿名不能读取。投影和点赞表不开放客户端直接读写，只通过有界、鉴权 RPC 操作。
- 正文图片及头像继续存在私有 Storage bucket。正文精确匹配当前公开投影引用的作者本人路径，社区评价精确匹配当前可见评价引用的评价者本人路径；不能用外部用户路径扩大访问，不公开整桶。评价附件来自当前评价者自己的账户、交易和上传记录，不能用被评价人的私人账本填充编辑器。
- 正文及评价图片通过鉴权下载后生成临时 Blob URL；组件卸载、换用户或换图片时释放，不跨次访问缓存这些附件。头像使用独立的当前查看账户内存缓存：按接口实例及服务端返回的 immutable path 定位，先解码再展示，保留最多 64 个／16 MiB、5 分钟；正在显示的头像由组件持有至卸载。退出登录或切号立即清除，包括已淘汰但仍显示的引用，旧下载不能恢复缓存。不写 localStorage/IndexedDB，不持久化帖子正文或缓存权限结果；当前已显示列表正文只可按下述详情流程在同一账户和作用域内复用。已设置自定义头像时，首次下载只显示中性占位，不先展示旧预设；没有自定义头像才使用预设。换头像必须换路径。撤回后新的附件下载会被拒绝；已经下载到阅读者设备上的内容无法追溯收回。

设置页头部与投资动态的本人身份复用 `reviewIdentityDb` 展示缓存：按当前账号同步读取昵称和已解码头像，重新挂载不能先清空图片再显示旧预设；未知或无可用自定义图时用中性占位，仅明确 `avatarPath === null` 才使用默认头像。读取失败保留同账号已确认身份，退出或切号清除，旧异步结果不能恢复。此缓存只供展示，编辑资料仍实时读取完整 profile 与强制更新头像路径，保存沿用原 compare-and-swap 校验，不能把显示缓存当作编辑基线。DEV 验收入口 `?devPreview=1&tab=settings&settingsAvatarCache=1` 使用同一设置页与身份缓存实现、只读本地示例图片，可切换 Tab 验证重挂载。

## 评论回复

评论正文、评论者昵称和“回复”按钮可打开回复编辑器，显示“回复 @昵称”。回复归入原评论的讨论组，默认折叠并显示回复总数，展开后只缩进一层并用细连接线区分；回复的回复保留准确的“回复 @昵称”，不无限向右嵌套。保留正文和附件能力；评分与评价标签仅用于直接评价博文，回复评论不显示评分、预设标签、自定义标签或历史标签。新建和编辑回复均提交 `score: null` 与 `tags: []`，隐藏的旧评分和标签不能使空回复可提交。读取旧记录保持兼容，不能因为历史回复仅有评分或标签而让整个评论列表读取失败，也不批量删除历史内容。评论与针对不同对象的回复分别保存草稿。不能让图片、附件或操作菜单的点击误触回复。

回复可以指向作者自评或社区评价，包括对回复继续回复。所有回复都写入独立社区评价表，即使发帖者本人回复其他用户，也不能把内容写回原帖作者自评。保存通过 `save_review_community_evaluation_v2` 接收 `{kind, id}` 目标，服务端锁住父帖并校验目标存在、未删除、属于同一帖子，实际目标作者与昵称由服务端确定。编辑不得更换回复目标，旧保存 RPC 也不能清掉已有回复关系。

响应的 `replyTo` 只包含目标类型、ID、作者 ID、当前昵称与可用状态，不复制目标正文。原评论删除后已有回复保留，并标明原评论已删除；不能继续创建指向已删除目标的新回复。回复与评价一同计入评论数，每人只可改删自己的回复。可见范围始终继承父帖，私密后仅原帖作者可读取，其他用户不能继续读取或回复。自动时间线仍保持个人视角。

### 分组评论、点赞与新帖提醒

增量迁移 `supabase/review_thread_interactions_20261108.sql` 先于本批前端部署。根评论每页最多 20 条，组内回复每页最多 50 条；服务端沿稳定 `{postId, kind, id}` 关系计算分组、直接回复数和讨论组总数，不以当前已加载的数组长度冒充总数。删除原评论保留占位及后续讨论；通知可以直接定位未在首屏的根评论或回复，同时保留完整分页。旧作者评价缺少真实 `createdAt` 时仍显示原日期，内部排序键不能冒充发布时间。

每条评论与回复共用心形点赞和回复图标，零值只显示图标，非零显示数字，不再附加“点赞”文字。点赞是唯一键上的期望状态写入，重复请求不叠加，失败回滚；每次操作在服务端重新校验登录账号、父帖可见范围和目标是否存在。私密博文及时间线仅本人可操作；合并时间线仍按各原始评价容器读取与写入。评论点赞本批只保存反应数据，尚不生成站内消息；现有帖子点赞、评论、评分和回复通知保持原合同。

底部“动态”角标与铃铛互动未读数独立，只统计其他用户当前仍公开的新普通博文。首次启用以当前云端游标建立基线，不将历史全部显示为未读；编辑、自己发帖、自动时间线与同一帖子再次公开不重复计数。原记录日期及排序保持不变。发布游标通过事务内锁定计数行生成，不能使用客户端时间或可乱序提交的 sequence 最大值作为已读边界。

点击底部“动态”打开公开“全部”。列表读取前捕获云端边界，成功显示无筛选的公开全部后仅标读该边界；私密、分类、搜索、详情、后台及读取失败不清除。加载期间新发的内容保留提醒，旧响应、旧账号及较早的标读不得覆盖较新状态。已读位置按账号存云端，前台每 30 秒检查，恢复前台合并刷新；不新增行情请求。公开帖子撤回或删除后不再计入数字。

已有当前账户 scope 的云端边界时，进入全部直接复制该旧边界，不再等待另一个 unread 请求；首次没有边界时仍等待读取。不得用列表请求发出后才得到的新边界标读，加载期间的新帖必须继续保留提醒。

### 站内消息提醒

投资动态右上角铃铛进入消息页，按全部、评论与回复、点赞、评分筛选，支持未读数、逐条已读与全部已读。新互动由 `supabase/review_activity_notifications_20261108.sql` 在服务端同一事务生成，deferred constraint trigger 读取最终评价与回复目标，兼容 v1 保存和 v2 后挂目标的调用顺序。不上报前端回调发消息，不补发既有历史互动，不接浏览器推送或短信。通知只存实体引用与版本，列表的短正文和当前头像每次按权限重新读取，不复制账户、交易或正文。

`reviewNotificationRepository` 的列表、未读数、标读与目标定位统一复用 `reviewSessionGuard`，每个 RPC 前后核对本地会话与身份世代，发出前同步检查；服务端仍核对 JWT、`p_expected_user_id`、收件人和内容当前可见性。正常会话不再附加两次远程 `getUser`，需要刷新 token 时仍可联网；旧客户端保留原远程双检。消息按原始 `(created_at,id)` 微秒游标分页，每页最多 20 条；全部已读使用已加载最新消息的实际游标，只标记该边界及之前的消息，防止吞掉并发到达的新消息。消息管理还支持勾选已加载未读消息，按 ID 每批最多 100 条标读，成功后才更新已读与未读数；部分失败保留未成功的选择，切账号或分类退出选择。选择期间暂停刷新以保留跨页选择，取消或全部成功后立即刷新。页面可见时每 30 秒更新，恢复前台事件合并；后台、弹窗、详情和卸载停止对应轮询。切换账户丢弃旧回包。

点击消息先重新读取目标与可见权限，再标读并跳到帖子；通知指向的评论即使不在前 20 条也可直接读取、定位和高亮。公开帖撤回或评论删除时清空失效目标，不能从旧分页恢复正文。消息时间沿用帖子和评论的“刚刚／分钟／小时／天前”。

- 点赞、评论、评分、回复区分事件类型；一条同时有文字和评分的评价可合并为一条提醒，避免重复打扰。
- 评论或评分的收件人为帖子作者，回复的直接收件人为被回复者；以稳定互动引用与收件人去重，自己的操作不提醒自己。
- 新建、修改和删除必须区分。相同 UUID 与 revision 的重试不产生第二条事件；点赞重复请求、取消点赞及反复切换范围不能反复制造新消息。修改评分可更新对应提醒，不冒充新评论。
- 通知列表、未读统计、详情跳转及附件读取都重新检查父帖当前权限和目标删除状态。转私密或删除后，其他人的旧提醒不得继续返回内容；重新公开也不能重放旧互动通知。取消赞和撤回的通知保留去重记录并标已读，恢复时不制造新的未读。
- 回复目标的身份由服务端保存，昵称随当前资料解析。不能靠展示文案或昵称反推收件人，也不能复用可变列表位置作为消息目标。

## 接口与状态

`reviewPublicRepository` 提供 feed、detail、desired-state like、社区评价分页／保存／删除、图片下载和头像下载。请求前后校验预期用户，所有公开及社区评价 RPC 在服务端核对 `p_expected_user_id` 与 `auth.uid()`，避免请求途中切号造成错误账号的写入。切换账号后的旧响应不得进入当前视图。

公开、分组互动及消息接口共用 `reviewSessionGuard`：正常客户端使用操作前后的本地 session 校验及同步身份事件世代，避免每个业务请求前后各增加一次远程 `getUser`。本地 session 仅防止错误账户发起请求和旧响应落地，不作为授权依据；服务端 JWT、`p_expected_user_id` 与各 RPC 显式权限检查及 RLS 保持。A→B→A、退出后同账号重新登录均作废旧请求；同账号 token 刷新不误伤。缺少 session／身份事件 API 的客户端回退原来的远程双检，支持 API 但 session 缺失或损坏时直接失败，不降级放行。RPC 拒绝和网络失败不能映射为空列表或标读成功。不缓存消息正文或授权结果；本地会话检查不承诺尚未到期 JWT 的远程即时撤销，若需强制下线即时生效，须另行实现服务端撤销策略。

社区评价按 `(created_at, id)` 分页，单页上限 20 条，保留微秒游标；列表和详情的 `commentCount` 为作者自评与社区评价总数。保存由服务端绑定实际登录用户，使用 UUID 和 revision 保证重试幂等与冲突检测；修改、删除仅允许评价者本人，非原帖作者操作时要求父帖仍公开。写入先锁定父帖，避免与撤回或删除竞态。正文、评分、标签和所有附件沿用原有正规模型逐字段校验，忽略未知 metadata；无有效内容的评价必须报错。

公开列表使用 `fetch_review_public_feed_v2` 与 `(record_date, published_at, id)` 游标，返回 `{recordDate, publishedAt, id}`，保留数据库微秒精度。`record_date` 是原记录日期，`published_at` 固定取源记录 `created_at`，不能使用转公开时间、修改时间或拼接的伪造时刻。列表、详情、后台合并、分页均遵循这一顺序；社区评价仍独立使用 `(created_at, id)`。旧 feed RPC 保留兼容已安装旧客户端。迁移只校正已有且仍明确公开的本人投影，保留其点赞与评价；不能回填私密记录。

从当前已显示公开列表进入详情时，立即复用同一账户、同一列表作用域的已有正文，并在后台重新请求当前公开记录；评论读取与详情核验并行，正文不等待评论。初次没有现成正文的通知／历史入口使用布局骨架，评论未返回时只在评论区域占位。此复用不写 localStorage／IndexedDB，也不建立跨会话正文缓存；返回列表沿用原滚动位置。后台核验之前，刚被撤回的已见正文可能短暂保留，不能把预览当作新的授权；写操作仍需服务端当前权限校验。详情或评论返回删除、私密、无权限或账户失效时，立即清除相关正文、评论与列表记录，并使更早请求失效；普通网络错误与撤回区分，保留已见正文并给出重试。切换账户或筛选不能复用旧 scope 的内容，旧回包不能复活撤回数据。点赞使用 `(post_id, user_id)` 唯一约束，同一用户只有一赞，重复请求幂等；请求中禁止重复点击，失败恢复原值，列表与详情共享点赞状态。数据库锁住对应公开记录，避免点赞与撤回之间产生孤立数据。

公开动态不能依赖本人数据刷新：其他作者发布时不会改变当前设备的私人记录。全局下拉刷新必须等待公开列表及已打开详情重新读取；再次选择公开范围也重新读取。公开页面在前台时每 30 秒检查一次，返回前台、恢复联网及页面恢复会合并触发更新；后台、设置页和编辑弹层暂停自动刷新。后台检查保留当前内容与滚动位置，失败显示重试提示，不能把旧空列表当成最新结果。所有响应继续校验账号、筛选和请求版本，翻页或点赞中的旧结果不得覆盖新的公开列表。刷新只调用公开动态接口，不触发额外行情请求或修改私人原表权限。

公开保存前检测公开 RPC 可用性。迁移未配置时明确提示错误，不能保存一个实际无法发布的“公开”状态；旧环境仍允许正常保存私密记录。加载失败、没有公开内容与没有匹配结果必须区分。

## 验证与上线顺序

本地 `ReviewJournalPreview` 使用隔离的示例记录和内存模拟接口，不写真实账户。首次默认打开公开动态，此后使用本机浏览范围偏好；`?devPreview=1&tab=review-journal&reviewScope=private` 可直接查看私密视图；`reviewPublicOwner=1&reviewScope=public` 提供包含本人公开评价的示例。示例模块只由 DEV 预览入口引入。

本地预览顶部的折叠“刷新验收”控件可先清空示例列表，再模拟其他作者发帖；模拟发布只改变内存数据源，不直接刷新 UI，用来验证前台定时读取和主屏幕 Web App 后台恢复。控件与示例接口不进入生产构建；全局下拉刷新另有实际 App 回调的等待和失败测试。

定向测试覆盖范围切换、新建博文默认公开、旧记录及旧草稿缺少 visibility 时保持私密、编辑保留原可见范围、草稿恢复、原记录及社区评价 CAS、请求切号、分页、点赞回滚、撤回详情和图片资源清理。SQL 测试支持 `PGLITE_MODULE_FILE` 指定本地 PGlite，使用多个独立用户及匿名角色实际执行迁移和 RLS；不连生产。社区评价额外覆盖评价者身份、跨用户改删拒绝、评分单独提交、撤回后禁止读取和写入、作者私密查看、重新公开及删除清理。日期覆盖旧帖转公开、再次公开、补记、编辑、同日微秒游标及翻页顺序；回复覆盖作者自评、社区评价、回复的回复、跨帖与已删除目标拒绝、目标不可变、旧接口兼容和删除原评论后保留回复。多连接并发尚未实测。

涉及权限、数据库写入与 schema 的改动使用 FULL 门禁。新增评价公开需执行多用户 PGlite 集成测试、增量迁移后聚合检查及匿名 RLS REST 检查，再通过 GitHub／Vercel 发布前端。移动端验证正文与评价入口、作者改删、私密切换；未使用真实双账号做写入时必须如实记录，不能把空列表或迁移成功单独视为全部功能验收通过。

社区评价迁移与旧前端兼容，先迁移后发布。若前端发布失败可以回到上一版本，保留独立评价数据与权限边界；数据库问题通过新的增量迁移修复，不直接删除已经产生的评价或恢复宽松权限。已安装 iPhone 主屏幕 Web App 的隔离预览已验证他人帖评分单独发布、修改评分和文字、本人删除以及计数更新；该验收使用示例数据，不代表向真实用户帖子写入过测试评价。

本批集成预览入口：`?devPreview=1&tab=home&reviewUnread=1&reviewThreads=1&reviewScope=public`；示例接口与实际 Hook 配合，支持独立点赞、回复分页与新帖边界验证，全部写入仅发生于内存。

详情加载隔离验收入口：`?devPreview=1&tab=review-journal&reviewThreads=1&reviewScope=public&reviewDetailLoading=1`。点开示例后可保持详情请求未完成，核对正文与评论已显示，再完成请求或模拟网络失败；转私密仍使用原示例控件。所有数据与延迟控制仅在 DEV，不访问生产账户。
