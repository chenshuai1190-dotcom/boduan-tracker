# 投资动态的公开、私密与点赞

公开动态基础迁移 `review_public_activity_20261108.sql` 已于 2026-11-08 应用，v10.7.9.601 已发布。后续评价公开改动必须先应用 `supabase/review_public_replies_20261108.sql` 增量迁移，再发布前端；迁移与发布结果以实际验收为准。

## 展示范围

| 入口 | 内容 | 排序 |
| --- | --- | --- |
| 全部 → 公开动态 | 所有已登录 Quote 用户明确公开的普通博文，包括自己的公开博文 | 公开发布时间倒序；同时间按公开 ID 排序 |
| 全部 → 私密 | 自己的私密博文及设置允许混入的自动时间线 | 原有记录日期倒序 |
| 复盘日志／投资心得 | 自己对应分类的全部博文，包含自己已公开和私密的博文 | 原有分类排序和置顶规则 |
| 时间线 | 自己的自动时间线 | 原有时间线规则 |

公开列表与详情沿用私密博文的作者行、日期、正文及安全区布局；自己公开的博文通过右上角操作菜单直接编辑或删除，操作使用本人完整原记录，不能用公开投影覆盖原记录中的附件或评价。其他作者的博文不展示管理入口。

公开／私密切换只作用于“全部”。分类页始终是个人视角，不能把它们接到跨用户公开查询。自动时间线及其评价容器保持私密，不能通过修改 metadata 公开。

首次新增博文默认“公开可见”；旧记录及旧草稿缺少 visibility 时仍按私密处理，编辑保留原可见范围。发布或编辑可以选择“公开 · Quote 用户可见”，保存后列表切换到对应范围。修改公开正文保留原公开时间；撤回后重新公开产生新的公开时间并重新累计点赞。

当前设备通过按 userId 隔离的 localStorage，分别记住用户明确选择的“全部”浏览范围（feedScope）与新建博文发布范围（publishVisibility）。首次、缺失或非法值默认公开；两个偏好互不覆盖，只保存 public／private，不保存正文。旧记录和已恢复草稿优先使用自身范围，打开编辑或自动切换列表不更新习惯，只有用户显式选择时才更新。无登录用户不读写；存储不可用不阻断操作。发布界面保留范围选择，移除其说明提示；公开列表不再显示额外说明与独立刷新按钮，加载失败仍可重试。

## 数据与权限边界

- `disciplines`、`review_logs`、账本及完整个人资料继续使用原有本人权限。公开读取绝不能直接放开原表的 RLS。
- 迁移 `supabase/review_public_activity_20261108.sql` 创建 `review_public_posts` 安全投影。源记录写入触发器只提取正文、日期、股票代码、正文图片、市场快照及明确允许公开的评价字段；作者只返回昵称、头像预设及当前头像路径。
- 评价继承所属博文的可见范围，没有独立开关。用户已确认评价文字、评分、标签、图片、市场和账户快照、冻结交易引用一起公开；评价数据按既有正规模型逐字段投影，未知 metadata 和内部凭证不返回。主博文未明确授权的账户／交易原字段仍不外露。公开股票标签只筛选公开博文，不接入查看者或作者的私人买卖节点。
- 公开列表显示评论入口及评价数量；详情对所有已登录用户展示公开评价。作者仍使用本人的完整原记录新增、修改和删除评价；其他用户仅阅读，不开放跨用户评价写入。评价编辑器按博文范围显示“公开可见”或“仅自己可见”，不能继续硬编码私密。
- 源记录改为私密或删除时，同一事务删除正文及评价投影和关联点赞；新的正文、评价和评价图片读取均被收回。公开评价修改同步更新公开投影及更新时间，保留原公开发布时间与点赞。旧私密博文、自动时间线及其评价不通过回填公开。
- 公开仅指已登录的 Quote 用户；匿名不能读取。投影和点赞表不开放客户端直接读写，只通过有界、鉴权 RPC 操作。
- 正文图片及头像继续存在私有 Storage bucket。读取权限精确匹配当前公开投影引用的作者本人路径；不能用外部用户路径扩大访问，不公开整桶；评价图片仅在当前公开投影明确引用时允许读取。
- 图片通过鉴权下载后生成临时 Blob URL；组件卸载、换用户或换图片时释放。撤回后新的下载会被拒绝；已经下载到阅读者设备上的内容无法追溯收回。

## 接口与状态

`reviewPublicRepository` 提供 feed、detail、desired-state like、正文图片下载和头像下载。公开读取、点赞及下载在请求前后校验预期用户；三个公开 RPC 还必须在服务端核对 `p_expected_user_id` 与 `auth.uid()`，避免请求途中切号造成错误账号的写入。切换账号后的旧响应不得进入当前视图。

公开列表使用 `(published_at, id)` 游标，保留数据库微秒精度。详情重新请求当前公开记录，撤回显示“不再公开”。点赞使用 `(post_id, user_id)` 唯一约束，同一用户只有一赞，重复请求幂等；请求中禁止重复点击，失败恢复原值，列表与详情共享点赞状态。数据库锁住对应公开记录，避免点赞与撤回之间产生孤立数据。

公开动态不能依赖本人数据刷新：其他作者发布时不会改变当前设备的私人记录。全局下拉刷新必须等待公开列表及已打开详情重新读取；再次选择公开范围也重新读取。公开页面在前台时每 30 秒检查一次，返回前台、恢复联网及页面恢复会合并触发更新；后台、设置页和编辑弹层暂停自动刷新。后台检查保留当前内容与滚动位置，失败显示重试提示，不能把旧空列表当成最新结果。所有响应继续校验账号、筛选和请求版本，翻页或点赞中的旧结果不得覆盖新的公开列表。刷新只调用公开动态接口，不触发额外行情请求或修改私人原表权限。

公开保存前检测公开 RPC 可用性。迁移未配置时明确提示错误，不能保存一个实际无法发布的“公开”状态；旧环境仍允许正常保存私密记录。加载失败、没有公开内容与没有匹配结果必须区分。

## 验证与上线顺序

本地 `ReviewJournalPreview` 使用隔离的示例记录和内存模拟接口，不写真实账户。首次默认打开公开动态，此后使用本机浏览范围偏好；`?devPreview=1&tab=review-journal&reviewScope=private` 可直接查看私密视图；`reviewPublicOwner=1&reviewScope=public` 提供包含本人公开评价的示例。示例模块只由 DEV 预览入口引入。

本地预览顶部的折叠“刷新验收”控件可先清空示例列表，再模拟其他作者发帖；模拟发布只改变内存数据源，不直接刷新 UI，用来验证前台定时读取和主屏幕 Web App 后台恢复。控件与示例接口不进入生产构建；全局下拉刷新另有实际 App 回调的等待和失败测试。

定向测试覆盖范围切换、新建博文默认公开、旧记录及旧草稿缺少 visibility 时保持私密、编辑保留原可见范围、草稿恢复、原记录评价 CAS、请求切号、分页、点赞回滚、撤回详情和图片资源清理。SQL 测试支持 `PGLITE_MODULE_FILE` 指定本地 PGlite，使用三个独立用户及匿名角色实际执行迁移和 RLS；不连生产。已执行通过，多连接并发尚未实测。

涉及权限、数据库写入与 schema 的改动使用 FULL 门禁。新增评价公开需执行多用户 PGlite 集成测试、增量迁移后聚合检查及匿名 RLS REST 检查，再通过 GitHub／Vercel 发布前端。移动端验证正文与评价入口、作者改删、私密切换；未使用真实双账号做写入时必须如实记录，不能把空列表或迁移成功单独视为全部功能验收通过。
